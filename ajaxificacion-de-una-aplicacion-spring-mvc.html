    7. Ajaxificación de una aplicación Spring MVC

    7.1. El papel de AJAX en una aplicación web

    Hasta ahora, los ejemplos de aprendizaje que hemos estudiado han tenido la siguiente arquitectura:

    Para pasar de una vista [View1] a otra [View2], el navegador:

    • envía una solicitud a la aplicación web;
    • recibe la vista [View2] y la muestra en lugar de la vista [View1].

    Este es el patrón clásico:

    • solicitud del navegador;
    • el servidor web genera una vista en respuesta al cliente;
    • visualización de esta nueva vista por parte del navegador.

    Desde hace varios años, existe otro modo de interacción entre el navegador y el servidor web: AJAX (JavaScript asíncrono y XML). Esto implica interacciones entre la vista mostrada por el navegador y el servidor web. El navegador sigue haciendo lo que mejor sabe hacer —mostrar una vista HTML—, pero ahora está controlado por JavaScript incrustado en la vista HTML mostrada. El diagrama es el siguiente:

    • En [1], se produce un evento en la página mostrada en el navegador (un clic en un botón, un cambio de texto, etc.). Este evento es interceptado por el JavaScript (JS) incrustado en la página;
    • En [2], el código JavaScript realiza una solicitud HTTP tal y como lo habría hecho el navegador. La solicitud es asíncrona: el usuario puede seguir interactuando con la página sin que se bloquee mientras espera la respuesta HTTP. La solicitud sigue el flujo de procesamiento estándar. Nada (o muy poco) la distingue de una solicitud estándar;
    • En [3], se envía una respuesta al cliente JS. En lugar de una vista HTML completa, lo que se envía suele ser una vista HTML parcial, un feed XML o JSON (JavaScript Object Notation);
    • En [4], JavaScript recupera esta respuesta y la utiliza para actualizar una región de la página HTML mostrada.

    Para el usuario, se produce un cambio en la vista porque lo que ve ha cambiado. Sin embargo, no se recarga la página completa; en su lugar, solo se produce una modificación parcial de la página mostrada. Esto ayuda a que la página sea más fluida e interactiva: al no recargarse la página completa, podemos gestionar eventos que antes no se podían manejar. Por ejemplo, ofrecer al usuario una lista de opciones a medida que escribe caracteres en un campo de entrada. Con cada nuevo carácter escrito, se envía una solicitud AJAX al servidor, que a continuación devuelve sugerencias adicionales. Sin AJAX, este tipo de asistencia en la entrada era antes imposible. No podíamos recargar una nueva página con cada carácter escrito.

// requête HTTP
function executePost(deferred, sendMeBack, url, post) {
    // on fait un appel Ajax à la main
    $.ajax({
        headers : {
            'Accept' : 'application/json',
            'Content-Type' : 'application/json'
        },
        url : url,
        type : 'POST',
        data : JSON3.stringify(post),
        dataType : 'json',
        success : function(data) {
            // on mémorise la session
            if (data.session) {
                session = data.session;
            }
            // on rend le résultat
            deferred.resolve({
                "status" : 1,
                "data" : data,
                "sendMeBack" : sendMeBack
            });
        },
        error : function(jqXHR) {
            // on rend l'erreur
            deferred.resolve({
                "status" : 2,
                "data" : jqXHR.responseText,
                "sendMeBack" : sendMeBack
            });
        }
    });
}

      2. un objeto JS que se devolverá a la capa [presentation];

      4. el valor que se va a enviar como objeto JS;
